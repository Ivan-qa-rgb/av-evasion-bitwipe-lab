# Technical Analysis

## 1. Вектор первоначального доступа

- **Тип:** фишинговое письмо с вложением.
- **Вложение:** `Invoice_Q3_2024.docm` (Word-документ с макросами).
- **Тема:** «Просроченный счёт» (типичная социнженерная уловка для бухгалтерии).
- **Действие пользователя:** открытие документа и включение макросов.

На этом этапе срабатывает классическая техника **T1566.001 – Spearphishing Attachment** (MITRE ATT&CK).

---

## 2. Доставка и запуск лоадера

После включения макросов:

1. Макрос выполняет PowerShell-команду для загрузки файла с удалённого сервера.
2. PowerShell сохраняет исполняемый файл в:
   ```text
   %TEMP%\svchost_.exe
   ```
   (камуфляж под системный процесс).
3. Файл представляет собой обфусцированный лоадер:
   - секции кода модифицированы;
   - строки зашифрованы;
   - хеш не совпадает с известными сигнатурами.

Это соответствует техникам:

- **T1059.001 – Command and Scripting Interpreter: PowerShell**
- **T1027 – Obfuscated Files or Information**

---

## 3. Техника «затирания битов» (высокоуровневое описание)

В рамках симуляции атаки в изолированной лаборатории был создан учебный образец, имитирующий поведение обфусцированного лоадера. На концептуальном уровне использовались:

- **Padding** – добавление блоков нулей / NOP-инструкций для изменения хеша.
- **Dead-code insertion** – вставка неисполняемых фрагментов кода, не влияющих на логику.
- **Instruction substitution** – замена инструкций на эквивалентные.
- **Encoded payload** – шифрование полезной нагрузки (XOR, кастомные алгоритмы) с встраиванием расшифровщика.
- **Self-modifying code** – код изменяет собственные байты в памяти перед выполнением.

Файл на диске выглядел как безобидная утилита, но при запуске расшифровывал и внедрял в память вредоносный модуль.

> Все описанные техники приведены в образовательных целях. В репозитории нет рабочего вредоносного кода или инструкций по его созданию.

---

## 4. Выполнение полезной нагрузки и персистентность

После запуска `svchost_.exe`:

1. Лоадер в памяти расшифровывает основной модуль.
2. Расшифрованный код инжектируется в процесс `explorer.exe`:
   - выделяется память с правами `PAGE_EXECUTE_READWRITE`;
   - используется `WriteProcessMemory` + `CreateRemoteThread` (или аналоги).
3. Создаётся запись в реестре для автозапуска:
   ```text
   HKCU\Software\Microsoft\Windows\CurrentVersion\Run
   "Updater" = "%APPDATA%\Microsoft\decryptor.dll, Run"
   ```

Техники MITRE ATT&CK:

- **T1055 – Process Injection**
- **T1547.001 – Boot or Logon Autostart Execution: Registry Run Keys**

---

## 5. Обнаружение атаки

Несмотря на обход статических сигнатур, сработали поведенческие механизмы:

- EDR зафиксировал:
  - выделение памяти с правами RWX в `explorer.exe`;
  - вызовы `VirtualAllocEx`, `WriteProcessMemory`, `CreateRemoteThread` из нетипичного образа.
- Сработало правило детекта на комбинацию:
  - создание удалённого потока в системный процесс из файла в `%TEMP%`.

Это привело к алерту в SIEM и запуску процедуры реагирования.

---

## 6. Артефакты на хосте

На заражённом хосте были обнаружены:

- Файлы:
  - `%USERPROFILE%\Downloads\Invoice_Q3_2024.docm`
  - `%TEMP%\svchost_.exe`
  - `%APPDATA%\Microsoft\decryptor.dll`
- Записи реестра:
  - `HKCU\...\Run` с подозрительной командой автозапуска.
- События Sysmon:
  - ProcessCreate для `svchost_.exe`;
  - ImageLoaded для `decryptor.dll`;
  - CreateRemoteThread / ProcessAccess между `svchost_.exe` и `explorer.exe`.
