# Recommendations

## 1. Технические контроли

### 1.1 Microsoft Defender ASR (или аналог)

Рекомендуется включить правила Application Control / ASR:

- Блокировка запуска исполняемых файлов из `%TEMP%` и `%APPDATA%`.
- Блокировка макросов в Office-документах, полученных из интернета.
- Запрет на создание процессов из Office-приложений (WinWord, Excel).

### 1.2 WDAC / AppLocker

- Разрешить запуск только подписанных и утверждённых приложений.
- Запретить для стандартных пользователей:
  - `rundll32.exe`, `mshta.exe`, `regsvr32.exe` (частые LOLBins).
- Ограничить запуск скриптов из пользовательских каталогов.

### 1.3 Контроль PowerShell

- Ограничить выполнение скриптов (ExecutionPolicy + GPO).
- Включить:
  - ScriptBlockLogging;
  - ModuleLogging;
  - Constrained Language Mode (где возможно).

### 1.4 ETW / Sysmon

- Развернуть Sysmon с конфигурацией типа SwiftOnSecurity на всех хостах.
- Включить ETW-подсистему Microsoft-Windows-Threat-Intelligence.
- Настроить сбор и корреляцию событий в SIEM.

### 1.5 Memory Scanning

- Использовать EDR с возможностью сканирования памяти:
  - поиск RWX-регионов;
  - детект известных паттернов (YARA в памяти).

### 1.6 Сетевая сегментация

- Изолировать критичные подсети (финансы, AD, серверы).
- Ограничить исходящий доступ к нестандартным портам.
- Внедрить DNS-фильтрацию и контроль User-Agent / JA3-фингерпринтов.

---

## 2. Детектирующие правила

- Настроить в SIEM корреляции на цепочки:
  - Office → PowerShell → запуск EXE из `%TEMP%`.
  - Процесс из `%TEMP%` → инъекция в системные процессы.
- Использовать правила Sigma из [`detections/sigma/`](../detections/sigma/) как базовые.
- Периодически проверять память хостов правилами YARA из [`detections/yara/`](../detections/yara/).

---

## 3. Организационные меры

- Провести целевой тренинг по фишингу для сотрудников (особенно бухгалтерия, HR, руководство).
- Внедрить песочницу для анализа вложений на почтовом шлюзе.
- Регулярно проводить threat hunting:
  - по поведенческим признакам (инъекции, RWX-память, аномальные цепочки процессов);
  - по сетевым аномалиям (редкие домены, необычные User-Agent, аномалии TLS).
- Проводить внутренние purple team-упражнения:
  - симуляция подобных атак;
  - проверка детектов и плейбуков SOC.

---

## 4. Улучшение процессов SOC

- Обновить плейбуки реагирования на инциденты с:
  - фишингом;
  - инъекциями в процессы;
  - подозрительной активностью PowerShell.
- Добавить в базу знаний SOC этот кейс как типовой сценарий.
- Периодически проводить тренировки L1/L2 на материале этого репозитория (разбор логов, написание правил).
